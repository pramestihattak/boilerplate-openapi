# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

### Backend (`cd backend`)
```bash
make build-backend      # Compile to bin/backend
make run-backend        # Build and run on port 8090
make tests              # Run tests with HTML coverage report
make generate-mocks     # Regenerate all mocks (uses mockgen)
make migrate-up         # Apply goose SQL migrations
make migrate-down       # Roll back goose SQL migrations
```

Run a single test:
```bash
go test ./service/auth/... -run TestRegister -v
```

### Definition / OpenAPI (`cd definition`)
```bash
make all                # Validate the spec (default)
make build              # Bundle src/main.yaml → api.yaml
make generate-gen       # Generate Go server code + TS types from api.yaml
```

**Code generation pipeline:** Edit YAML in `definition/src/` → `make build` → `make generate-gen` → regenerated files appear in `backend/api/api.gen.go` and `definition/gen/ts/types.ts`.

## Configuration

Copy `backend/env/sample.config` to `backend/env/config` (the app reads `env/config` relative to the working directory). The config is INI format read by Viper. JWT keys must be base64-encoded RSA PEM strings — set `jwt.privatePEM` and `jwt.publicPEM`.

## Architecture

### Request flow
```
HTTP → Chi middleware (RequestID, Logger, Recoverer, Timeout, WithAuth)
     → server/ (handler methods on *Server)
     → service/auth/ (business logic)
     → storage/auth/ (SQL via sqlx)
     → PostgreSQL
```

### Layer responsibilities

**`server/`** — HTTP handlers implementing the `api.StrictServerInterface` generated from the OpenAPI spec. Contains `errors.go` which maps domain errors → HTTP status codes and response bodies. JWT auth middleware (`middleware.go`) validates Bearer tokens and injects `userID` into context. To add a new protected endpoint, add its path to `restrictedAuthEndpoints` in `middleware.go`.

**`service/auth/`** — Business logic. Each operation is a separate file (`login.go`, `register.go`, etc.). Domain errors are defined in `errors.go` and mapped to HTTP responses in `server/errors.go`. The `AuthService` interface in `interfaces.go` is what handlers depend on.

**`storage/auth/`** — Raw SQL queries using `sqlx`. Implements the `PostgresStore` interface (split into `PostgresWriter` and `PostgresReader`). Each operation is a separate file. SQL strings are package-level `var`s above their functions.

**`pkg/jwt/`** — RS256 JWT sign/validate. `JWTInterface` is the dependency abstraction used by `server/`.

### Interface-based DI
Every layer depends on an interface, not a concrete type. Mocks live in `<package>/mock/` and are generated by mockgen from source files. After adding or changing an interface, run `make generate-mocks` from `backend/`.

### Adding a new endpoint
1. Add the path/schema to `definition/src/` YAML files and reference from `main.yaml`.
2. Run `cd definition && make build && make generate-gen` to regenerate `backend/api/api.gen.go`.
3. Implement the new method on `*server.Server` in a new file `server/<domain>.<action>.go`.
4. Add service interface method, implement in `service/<domain>/`, add storage queries in `storage/<domain>/`.
5. Register new domain errors in `server/errors.go` (`errStatusCode` and `errMessage` maps).
